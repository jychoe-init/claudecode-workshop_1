# 프롬프트 코치

진단 대상: $ARGUMENTS

진단 대상이 파일 경로이면 그 파일을 읽어 요청문으로 사용하세요. 비어 있으면 진단할 요청문을 붙여 달라고 한 번만 요청하고 멈추세요.

아래 세 섹션만 출력합니다.

### 1. 진단

기준마다 "충분" 또는 "부족"과 근거 한 줄을 표로 적습니다.

| 기준 | 확인할 점 |
|---|---|
| 목표 | 결과물이 무엇이고 누가 쓰는가 |
| 맥락 | 대상 파일, 데이터, 배경이 주어졌는가 |
| 형식 | 출력 구조, 길이, 언어가 정해졌는가 |
| 완료 기준 | 제대로 했는지 확인할 방법이 있는가 |
| 제약 | 하면 안 되는 것이 분명한가 |
| 과잉 강조 | IMPORTANT, CRITICAL, 반복 경고처럼 예전 모델용 강조가 있는가 |

### 2. 다시 쓴 프롬프트

원래 의도는 바꾸지 말고 "부족"인 기준만 보강한 요청문을 코드 블록 하나로 제시합니다. 대문자 강조나 위협하는 문구는 쓰지 않습니다.

### 3. 설정으로 옮길 항목

요청문에 매번 반복해 쓸 필요가 없는 내용을 골라 표로 정리합니다.

| 내용 | 옮길 곳 | 이유 |
|---|---|---|

옮길 곳은 아래 기준으로 고릅니다.

- `CLAUDE.md`: 모든 작업에 적용되는 팀 관행 ("우리는 이렇게 한다")
- `.claude/rules/*.md`: 특정 파일이나 경로에만 적용되는 규칙 (`paths:`)
- skill: 특정 작업에만 필요한 절차와 템플릿
- permissions: 반드시 막거나 허용해야 하는 도구 호출. 안내가 아니라 보장이 필요할 때
- hooks: 매번 자동으로 실행되어야 하는 검사와 후처리

마지막 줄에 "가장 먼저 적용할 1개"를 한 문장으로 추천합니다.
