# 코치 진행표 · lab2 사내 API 업무 자동화 (20분)

이 파일은 코치가 읽는 자료입니다. 예측 해설은 참가자가 예측과 실제를 워크시트에 적은 뒤에만 설명합니다. 코치는 사내 API를 직접 부르지 않습니다.

## 단계와 시간

| 단계 | 시간 | 참가자가 하는 일 | 다음으로 넘어가는 조건 |
|---|---|---|---|
| 1 목표 | 1 | `python3 tools/hr_fetch.py me`로 연결 확인 | 팀원 목록이 나옴 |
| 2 결정 | 4 | D1~D3 선택과 이유 | D1~D3 선택·이유 칸 |
| 3 작성 | 8 | 스킬 빈칸, 권한, (C면) `.mcp.json` | `check_lab2.py`에서 빈칸·권한 항목 통과 |
| 4 예측·실행 | 5 | P1~P4 예측 → 정상 요청, 까다로운 요청, 예측 실험 → 실제 기록 | P1~P4 실제 칸 |
| 5 확인 | 2 | 추적표, 반성, 검사 | `check_lab2.py` 실패 0 |

## 결정 해설

- **D1**: 휴가 신청은 쓰기가 있어 D3이 실제로 의미가 있습니다. 배포 보고는 조회만이라 안전하지만, 넓은 허용 패턴이 쓰기까지 열어 버리는지(P2) 확인하는 것은 똑같이 중요합니다.
- **D2**
  - A 주입: 스킬을 부르는 순간 명령이 실행되고 결과가 지시문에 박힙니다. Claude가 호출을 건너뛸 수 없고 토큰 사용이 예측 가능합니다. 대신 명령이 허용 목록에 없거나 실패하면 승인 창 없이 스킬 호출 전체가 중단됩니다. 요청마다 달라지는 조회(신청 기간의 팀 휴가)는 주입 시점에 날짜를 모르므로 B나 C가 맞습니다.
  - B Bash: Claude가 필요할 때 부릅니다. 판단에 따라 추가 조회도 합니다. 호출마다 권한 규칙이 적용되고, 실패하면 오류가 Claude에게 돌아가 대응할 수 있습니다.
  - C MCP: 도구 이름 단위로 권한을 줄 수 있어 조회(`get_*`)와 쓰기(`request_leave`)를 깔끔하게 나눕니다. 서버를 다른 스킬과 사람이 재사용합니다. 처음 한 번 프로젝트 서버 사용 승인이 필요합니다.
- **D3**
  - ask: 매번 승인 창. 가장 확실하지만 반복되면 습관적으로 누르게 됩니다. settings의 `ask` 규칙은 스킬의 `allowed-tools`보다 우선합니다.
  - 계획 먼저: 스킬이 신청 내용을 보여 주고 "진행"을 기다립니다. 사람이 한 번 확인하지만 그 확인은 대화 속 약속(문장 울타리)입니다. 권한은 ask로 함께 두면 설정 울타리까지 겹칩니다.
  - allow: 판단 규칙이 틀리거나 요청을 잘못 읽어도 실제로 신청됩니다.
- **알아 둘 동작**: `allowed-tools` 허용은 스킬을 부른 그 턴에만 유효하고, 사용자가 다음 메시지를 보내면 풀립니다. 그래서 계획 먼저 방식에서 "진행" 뒤의 신청은 `allowed-tools`가 아니라 settings 규칙을 따릅니다. 팀원 겹침을 물어본 뒤 이어지는 조회도 마찬가지입니다. 근거: [skills · Pre-approve tools](https://code.claude.com/docs/en/skills#pre-approve-tools-for-a-skill)

## 예측 해설 (예측·실제를 적은 뒤에만)

- **P1**: 승인 창은 뜨지 않습니다. 주입 명령의 권한 확인 결과가 allow가 아니면(평소라면 묻는 경우 포함) 스킬 호출 전체가 중단되고 오류 메시지만 남습니다(auto 모드 제외). `hr_fetch.py`는 Claude Code가 아는 읽기 전용 명령이 아니므로 `allowed-tools`나 설정의 allow가 필요합니다. 근거: [skills · Permission checks on injected commands](https://code.claude.com/docs/en/skills#permission-checks-on-injected-commands)
- **P2**: 스킬을 부른 턴 안에서 신청까지 가면 그렇습니다. `Bash(python3 tools/hr_fetch.py *)`는 접두 매칭이라 `request`까지 포함합니다. 계획 먼저 방식이면 "진행" 뒤는 다음 턴이라 `allowed-tools`가 풀려 승인 창이 뜹니다. 같은 패턴을 settings의 allow에 넣으면 턴과 관계없이 묻지 않습니다. 조회만 열려면 `Bash(python3 tools/hr_fetch.py member *)`, `Bash(python3 tools/hr_fetch.py leave *)`, `Bash(python3 tools/hr_fetch.py requests)`처럼 하위 명령까지 씁니다. `request*`(공백 없이)는 `requests`와 `request`를 둘 다 엽니다. MCP에서 `mcp__lab`이나 `mcp__lab__*`는 쓰기 도구까지, `mcp__lab__get_*`는 조회만 엽니다. 쓰기를 확실히 묻게 하려면 settings의 `ask`에 쓰기 규칙을 넣습니다.
- **P3**: 주입 명령이 0이 아닌 코드로 끝나 스킬 호출 전체가 중단됩니다. 실패를 보여 주는 것도 설계 대상입니다. 예: 주입 명령 끝에 `|| echo "조회 실패"`를 붙여 실패 문구가 지시문에 들어가게 하고, 지시문에 "조회 실패가 있으면 신청하지 말고 보고"를 씁니다. B나 C에서는 오류가 도구 결과로 Claude에게 돌아갑니다.
- **P4**: 스킬은 쓰이지 않습니다. 대신 Claude가 허용된 명령으로 직접 처리하려 할 수 있고, 그러면 스킬에 적은 판단 규칙(잔여, 주말, 팀원 겹침)을 거치지 않습니다. 자동 호출로 바꾸면 `description`이 트리거입니다.

## 힌트 3단계

| 단계 | 1 방향 | 2 위치 | 3 거의 답 |
|---|---|---|---|
| 결정 | 쓰기가 잘못 실행되면 무슨 일이 생기는지부터 생각해 보세요 | 워크시트 2번 표 | "계획 먼저 + ask: 날짜를 잘못 읽을 수 있어서 두 번 확인" |
| 조회 칸 | 조회가 두 번 필요합니다: 내 잔여, 기간의 팀 휴가 | 워크시트 3번 "연결 수단 쓰는 법"과 명령 표 | B: "`python3 tools/hr_fetch.py member ME`로 잔여 확인", "`... leave --from <시작> --to <종료>`로 팀 휴가 확인" |
| 판단 규칙 | 규칙마다 "신청하지 않고 무엇을 보고할지"를 정하세요 | 스킬의 "2. 판단" | "잔여 부족: 신청하지 않고 부족 일수와 잔여를 보고", "팀원 겹침: 겹치는 이름과 날짜를 보여 주고 계속할지 물음" |
| 권한 | 조회와 쓰기를 따로 생각하세요 | `allowed-tools`, `.claude/settings.json`의 ask | `allowed-tools: Bash(python3 tools/hr_fetch.py member *) Bash(python3 tools/hr_fetch.py leave *)`, 쓰기는 ask에 `Bash(python3 tools/hr_fetch.py request *)` |
| MCP | 서버 등록, 도구 권한, 지시문의 도구 이름 세 군데 | 워크시트의 `.mcp.json` 예시 | 권한 `mcp__lab__get_*` allow, `mcp__lab__request_leave` ask |

3단계 뒤에도 막히면: D1을 배포 보고, D2를 B로 바꿔 조회만 하는 스킬을 먼저 완성합니다.

## 자주 생기는 문제

| 증상 | 원인 | 안내 |
|---|---|---|
| `hr_fetch.py me`가 연결 실패 | 로컬 모드인데 서버가 꺼짐, 또는 사내망 차단 | 다른 터미널에서 `bin/lab server`, 강사에게 클라우드 주소 확인 |

| 스킬이 바로 중단됨 | 주입 명령이 허용 안 됨 또는 실패 | P1·P3 해설 (예측을 적은 뒤) |
