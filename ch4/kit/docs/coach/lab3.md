# 코치 진행표 · lab3 프롬프트 점검·배포 (18분)

이 파일은 코치가 읽는 자료입니다. 예측 해설은 참가자가 예측과 실제를 워크시트에 적은 뒤에만 설명합니다.

## 단계와 시간

| 단계 | 시간 | 참가자가 하는 일 | 다음으로 넘어가는 조건 |
|---|---|---|---|
| 1 목표 | 1 | 두 도구의 경계 읽기 | — |
| 2 결정 | 3 | D1(프롬프트·모델·쓰는 곳), D3(넘기는 방법) | D1, D3 칸 |
| 3 코치 실행·작성 | 5 | `/prompt-coach` 실행, 변경 채택, 최종본 붙이기, D2 | 워크시트 3번 코드 블록, D2 칸 |
| 4 측정 | 4 | P1 예측 → `usage_log.sh` 두 번 → 실제 | `usage.csv` 2행, P1 실제 |
| 5 감사 | 2 | P2 예측 → `/doctor prompt-audit` → 1건 이상 수정 | P2 실제, 검사의 감사 항목 통과 |
| 6 배포 | 3 | `.gitignore`, README 세 줄, 커밋 | `check_lab3.py` 실패 0 |

## 결정 해설

- **D1**: 모델과 쓰는 곳이 바뀌면 적용되는 근거가 달라집니다. 예: Opus 5.5 채팅이면 "신중히 생각하라" 제거(O3), Sonnet 5.5 JSON 판단 작업이면 "Think the problem through before you answer."(S3), Fable 5.1이면 서식 금지 규칙 제거(F5). Haiku 4.5는 전용 페이지가 없어 공통 원칙만 적용합니다.
- **D2**: 모든 변경을 채택할 필요는 없습니다. 근거 링크를 열어 "내 상황에 맞는가"로 고릅니다. 예시 3~5개 추가는 정확도를 올리지만 입력 토큰이 늘어납니다.
- **D3**
  - 프로젝트 커밋: `.claude/`를 저장소에 넣으면 저장소를 받는 사람에게 적용. 각자 local 설정으로 덮을 수 있음
  - 플러그인: 여러 저장소에 같은 스킬·에이전트를 설치. 사용자가 고름
  - Managed 설정: 조직이 강제. 사용자가 끌 수 없음. 보안 deny처럼 꼭 지켜야 하는 것에 맞음

## 샘플 프롬프트 진단 포인트 (참가자가 막힐 때 방향만)

- **A (대화)**: 대문자·느낌표 강조와 "대충 하지 마"(B9), "신중하게 깊이 생각"(Opus 5.5 O3), "마크다운 쓰지 마, 목록 쓰지 마"(B7, Fable 5.1 F5), 메모가 지시와 섞임(B4·B6), 독자와 목적 없음(B2)
- **B (스킬)**: "모든 도구 최대한", "애매하면 무조건"(B8·B9), 추론을 `<reasoning>`에 전부 적게 함(O2·S5·F2, `reasoning_extraction`), 세기·정렬이 필요한 JSON(S3). 스킬이면 effort는 frontmatter `effort:`
- **C (API)**: prefill(B10, 4.6 계열부터 400), "도구 호출 최소화"(Sonnet 5.5 S4), 분류 기준 정의와 예시 없음(B1·B3)

## 예측 해설 (예측·실제를 적은 뒤에만)

- **P1**: 정답은 없습니다. 추론을 응답에 쓰게 하던 지시나 과잉 강조를 지우면 출력 토큰이 대개 줄고, 예시와 맥락을 더하면 입력 토큰이 늘어납니다. 비용만 보지 말고 `.usage/<라벨>.md`의 결과를 함께 비교하게 하세요. 주의: `-p` 실행도 `CLAUDE.md`를 읽습니다. 감사 전후에 측정하면 조건이 달라지므로 두 측정은 같은 CLAUDE.md 상태에서 합니다.
- **P2**: 정답은 없습니다. 내 스킬에서 흔히 나오는 것: 없는 파일 참조, 대문자 강조, 다른 파일과 모순되는 규칙. CLAUDE.md에는 세 가지를 심어 두었습니다: `<thinking>` 강제와 IMPORTANT/CRITICAL(예전 모델용 지시), 탭 ↔ `.claude/rules/code-style.md`의 스페이스 2칸(파일 간 모순), `npm run test:unit`(package.json에 없는 참조).

## 힌트 3단계

| 단계 | 1 방향 | 2 위치 | 3 거의 답 |
|---|---|---|---|
| 코치 실행 | 모델, 쓰는 곳, 프롬프트 세 가지가 필요합니다 | `samples/prompts.md` | `/prompt-coach sonnet-5-5 스킬 samples/prompts.md B` |
| 채택 | 변경표의 근거 링크를 하나씩 열어 보세요 | 변경표의 근거 칸 | "S3 채택: 세기·정렬이 있어서 / 예시 추가 보류: 입력 토큰 증가" |
| 측정 | 같은 모델, 다른 라벨 | 워크시트 4번 명령 | `tools/usage_log.sh -m sonnet-5-5 original "$(cat a.txt)"` |
| 감사 | 찾은 항목 하나만 고치면 됩니다 | `CLAUDE.md`의 "응답 방식"과 "명령" | thinking 강제 줄 삭제, 또는 `test:unit` 줄을 `npm test`로 |
| 배포 | 커밋하면 안 되는 파일 네 가지 | `.gitignore`, `git status` | `.env`, `.claude/settings.local.json`, `usage.csv`, `.usage/` 추가 후 커밋 |

3단계 뒤에도 막히면: 샘플 A를 Opus 5.5 대화로 고정해 진행합니다.

## 자주 생기는 문제

| 증상 | 원인 | 안내 |
|---|---|---|
| `/doctor prompt-audit`가 없음 | Claude Code 2.1.283 미만 | `claude update`. 안 되면 "CLAUDE.md와 .claude/rules를 읽고 모순, 없는 참조, 예전 모델용 강조를 찾아 줘"로 대체 |
| `usage_log.sh`가 모델 오류 | 제공자별 모델 ID 차이 (Bedrock 등) | `-m`에 그 환경의 모델 ID를 그대로, 또는 `-m` 생략 |
| `usage.csv`가 커밋됨 | `.gitignore`보다 먼저 add | `git rm --cached usage.csv` 후 다시 커밋 |
| settings.local.json이 git에 보임 | setup이 만든 파일이라 자동 제외 대상이 아님 | `.gitignore`에 추가 (Claude가 직접 만든 경우에만 자동 제외됨) |
