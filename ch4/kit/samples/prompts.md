# lab3 점검용 프롬프트

예전 모델에 맞춰 쓰던 습관이 섞인 프롬프트 3개입니다. 하나를 골라 `/prompt-coach`로 점검하거나, 내가 실제로 쓰는 프롬프트를 가져와도 됩니다.

---

## A. 주간보고 요약 (쓰는 곳: 대화)

의도: 팀장에게 보낼 주간보고 초안을 메모로부터 만든다.

```text
IMPORTANT: 당신은 세계 최고의 보고서 작성 전문가입니다. 아래 메모를 읽고 주간보고를 쓰세요.
반드시 신중하게 깊이 생각한 다음 답하세요. 절대로 대충 하지 마세요!!!
마크다운 쓰지 마. 목록 쓰지 마. 너무 길게 쓰지 마.
- 월: i18n 설계 리뷰, 영어·한국어 먼저
- 화: i18n 모듈 1차 구현, PR 올림
- 수: 빈 이름 입력 시 "Hello, !" 버그 제보
- 금: 10/15 릴리스는 en/ko만, 빈 이름은 guest 처리로 결정
요약해 줘.
```

---

## B. 배포 실패 분석 (쓰는 곳: 스킬 지시문)

의도: 최근 배포 이력에서 실패 원인을 찾아 팀에 공유할 요약을 만든다.

```text
CRITICAL: 반드시 사용 가능한 모든 도구를 최대한 많이 사용해서 빠짐없이 철저하게 조사하라.
조금이라도 애매하면 무조건 도구를 다시 호출하라.
답하기 전에 너의 추론 과정을 <reasoning> 태그 안에 하나도 빠짐없이 전부 적은 다음 결론을 적어라.
결과는 JSON으로만 출력하라. 서비스별 실패 횟수를 세고 가장 위험한 서비스 순으로 정렬하라.
```

---

## C. 휴가 신청 분류 (쓰는 곳: API 시스템 프롬프트)

의도: 사내 메신저로 들어온 휴가 관련 요청을 분류해 담당 처리기로 넘긴다.

```text
너는 휴가 신청 분류기다. 도구 호출은 꼭 필요할 때만 최소한으로 해라.
사용자 요청을 신청, 취소, 문의 중 하나로 분류하라.
(구현 메모: JSON을 강제하려고 마지막 assistant 턴에 {"category": " 를 미리 채워서 보낸다)
```
